# 安全说明与删除防护机制

本文描述 `appdir clean` 的所有防护层，以及它们各自防护的具体事故。

## 防护层（自外向内）

1. **显式确认**：没有 `--yes` 一律是 dry-run，只预览不删除。
2. **账本关联**：只能删除账本里有记录的目录；账本里没有的路径一律拒绝（`no-ledger-row`）。
   账本记录只能由"确认过的新建目录"产生，不是磁盘快照差分。
3. **监视根/卷根不可删**：监视根本身、`C:\` 等卷根直接拒绝（`would-delete-root`），
   即使有旧记录也拒绝。
4. **删除前身份校验**：删除前重新核对目录当前身份（创建时间等元数据）与账本记录一致；
   目录被删后重建过的路径会被标记 `needs-review` 并拒绝（`identity-changed`）。
5. **两步删除**：先把目录改名为 `<名字>.appdir-todelete-<时间戳>`。
   改名在有文件被占用时会**硬失败**——这是刻意设计：Rust 的 `remove_dir_all` 在
   程序还开着目录内文件时可能"成功"删除并静默留下悬挂对象。改名成功才执行真正删除；
   失败则目录原样保留、账本状态不变。
6. **备份**：`--backup` 先把目录完整复制到账本数据目录的 `backups\` 下再删除。

## 不会发生的事

- 不会删除账本外的路径（即使你把路径敲对了）。
- 不会因为路径同名就删——同名但身份不同的目录会被拦截。
- 不会删除被占用的目录然后假装成功。
- 不会在被监视目录里写任何账本/日志文件（账本在独立数据目录）。

## 数据存放

- 账本与备份：`--data-dir` 指定的目录（SQLite + `backups\`）。
- 监视目录内零写入。

## 已知边界

- 账本只记录"驱动/采集器运行期间"的新建目录；采集器未运行时发生的创建没有历史
  （工具不做全盘扫描回溯）。
- 删除防护依赖账本正确性；账本数据目录本身受文件系统权限保护，请勿放置到
  可被任意进程写入的位置。
- ETW 来源需要管理员权限；以普通权限运行时会明确报错并退出，不会降级成"猜归属"。
